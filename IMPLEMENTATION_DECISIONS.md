# Implementation Decisions

- 2026-09-03 / Plan 1: BM25 via `rank-bm25` + regex tokenizer; index built once per `ProductIndex`, never per query.
- 2026-09-03 / Plan 1: `ProductIndex.search(query, top_k, filters)` is the frozen retrieval interface; semantic/hybrid (Plan 4) must match it.
- 2026-09-03 / Plan 1: Baseline eval uses lexical Recall@K / Precision@K / MRR + constraint match; LLM-judged contextual metrics deferred to Plan 3 with this dataset reused unchanged.
- 2026-09-03 / Spec deviation logged: explicit `POST /orders` route reserved for Plan 3 (source describes ordering via checkout flow without naming the route).
- 2026-09-03 / Plan 2: Money math — free shipping at subtotal >= 5000 (empty cart ships 0), else flat 49; 18% GST on (subtotal + shipping); all totals rounded to 2 decimals.
- 2026-09-03 / Plan 2: Real LLM provider adapter deferred to Plan 3; `LLMClient` protocol + `FakeLLM` are the seam. Agent/tests/demo never touch the network.
- 2026-09-03 / Plan 2: Order idempotency keys live in `OrderService` memory; durable key store moves to Plan 3 with the DB-backed state.
- 2026-09-03 / Plan 2: Cart API surfaces one error type (`CartError`); unknown product on add raises `CartError`, not `ProductNotFound`.
- 2026-09-03 / Plan 3: Runtime LLM = NVIDIA NIM or OpenRouter via OpenAI-compatible `/chat/completions` (stdlib urllib, no extra deps); selected by `LLM_PROVIDER` + `LLM_BASE_URL`/`LLM_API_KEY`/`LLM_MODEL`; keys env-only and redacted from traces.
- 2026-09-03 / Plan 3: Local DB = SQLite (stdlib, WAL) at `ASA_DB_PATH` for sessions/idempotency/orders/traces; catalog stays in-memory JSON; `FileSessionStore` retained for fast unit tests.
- 2026-09-03 / Plan 3: Tool args validated against schemas (`ToolValidationError`); LLM exceptions become failed agent results instead of crashes.
- 2026-09-03 / Plan 3: Response eval is deterministic (grounding/relevance over scripted scenarios); LLM-judge eval deferred to Plan 4 (needs live provider keys).
- 2026-09-03 / Plan 3: LLM seam takes the tools dict (`complete(messages, tools)`); OpenAI-format conversion is owned by the client (`to_openai_tools`), so descriptions stay attached.
- 2026-09-03 / Plan 3: API serves the same service gates as the CLI; `/chat` is 503 without LLM config; `POST /orders` is idempotent and revalidates before charging the mock adapter.
- 2026-09-03 / Plan 3: `SqliteStore` connects with `check_same_thread=False` (single-process FastAPI worker threads under WAL). Plan doc Task 4 snippet still shows the bare connect — code is ground truth; plan sync deferred.
- 2026-09-03 / Plan 3: `/chat` 503 test passes `llm=None`, not an empty `FakeLLM` (an empty script is a configured client whose exhaustion surfaces as a failed agent result). Plan doc Task 7 snippet + routes import (`SqliteOrderStore` lives in `app/checkout/service.py`) updated in code only; plan sync deferred.
- 2026-09-03 / Plan 4: Semantic (sentence-transformers all-MiniLM-L6-v2, cosine) + hybrid (RRF k=60) + optional cross-encoder rerank (ms-marco-MiniLM-L-6-v2) all honor the frozen search(query, top_k, filters) interface; no caller rewrite to switch variants.
- 2026-09-03 / Plan 4: `build_search_index` factory + `ASA_RETRIEVAL`/`ASA_RERANK` settings; default remains `bm25`. Measured decision (fixed 3-query dataset, k=5): every variant scores recall 1.00 / MRR 1.00 / constraint@1 1.00, so hybrid adds latency (semantic 27.5ms, hybrid+rerank 41.0ms vs bm25 0.1ms) without a quality win here; spec forbids claiming hybrid superiority without evidence. Semantic/hybrid still improve surface ordering (recorded demo). Rerank row reruns via `evaluation/experiment_eval.py --rerank`.
- 2026-09-03 / Plan 4: `constraint_match` now honors `in_stock: True` (availability + stock > 0), closing the Plan-1/2 flagged gap; filter semantics shared via `app/retrieval/filters.py` so every variant and the metric agree.
- 2026-09-03 / Plan 4: Embedders and rerankers lazy-load sentence-transformers (clear RuntimeError without the package); tests inject deterministic stubs and never load models. Model weights are cached locally (all-MiniLM-L6-v2, bge-small-en-v1.5, ms-marco reranker) so evals/demos run offline.
- 2026-09-03 / Plan 4: Experiment runner reports constraint@1 (top suggestion honors stated constraints); all-of-top-k was meaningless on a 6-product catalog. Latency excludes model load via a warmup query.
- 2026-09-03 / Plan 4: LLM-judge response eval (`evaluation/llm_judge_eval.py`) is key-gated: SKIPPED + exit 0 without LLM_PROVIDER/keys, verdict JSON parsed leniently, FakeLLM-tested.
- 2026-09-03 / Plan 4: Recorded demo `demo/record_demo.py` writes `demo/recording.md` (retrieval variant comparison + full purchase with confirmation gate, token auto-answered).
- 2026-09-03 / Plan 4 live-test fix: OpenAI-compatible tool calls now round-trip provider `id`s (`ToolCall.id`, echoed in the assistant message and sent as `tool_call_id` on `role: tool` results) — MiniMax via OpenRouter returned HTTP 400 without this.
- 2026-09-03 / Plan 4 live-test fix: `OpenAICompatibleClient` surfaces HTTP error bodies (truncated, key-free) and retries 429 rate limits with backoff (3 attempts) — free tiers rate-limit hard.
- 2026-09-03 / Plan 4 live-test fix: `demo/live_chat.py` is the re-runnable live smoke (loads .env last-wins, real agent run, asserts cart + AWAITING_CONFIRMATION checkout, never places an order). Verified 2026-09-03 against OpenRouter `minimax/minimax-m3:free`: grounded answer (search_products -> get_product -> search_reviews), totals 8499/0/1529.82/10028.82 INR, confirmation gate held. LLM-judge eval live: grounded True/4, hallucinated False/1.
- 2026-09-03 / UIUX pass (web app): cart clears after order placement (both API `/orders` and mock), so purchased lines never linger; slip shows a "That's ordered" recap after Done instead of falling back to the empty state.

- 2026-09-03 / UIUX pass: chat transcript + last order recap persist to localStorage and restore on reload (product-card buttons rebind); New session clears them.
- 2026-09-03 / UIUX pass: deterministic SVG "sticker" art per product (category line icon + palette color by product id) in cards, search results, and the product modal; product modal gains dialog role, ESC-to-close, and focus return.

- 2026-09-03 / Multi-role agents (per Aditya's review): single agent split into reach-bounded specialists over the SAME bounded ReAct engine — policy (only search_policy, read-only), catalog (read-only product/review tools), cart (catalog + cart ops + prepare). Roles differ in system prompt, tool allowlist, and budgets; a deterministic keyword router (app/roles.py classify) picks the role per message on /chat. confirm_checkout/place_order exist in NO role toolset — order capability stays human/API-only.
- 2026-09-03 / Policy surface added: data/policies.json demo corpus (shipping/GST, confirmation, returns, cancellation, mock payment, review trust, stock revalidation) + app/policy.py PolicyService (keyword-overlap retrieval returning exact rule bodies/ids); policy agent must quote rule ids and never invents figures.
- 2026-09-03 / Session memory: /chat persists plain-language turns per session (ShoppingSession.messages, capped at the last 16 by the API) and replays them into every agent run via ShoppingAgent._history_entries — only user/assistant content survives replay (system/tool scaffolding stripped, each entry truncated to 4k chars, window capped at 10). Fixes multi-turn context loss (the model previously "forgot" quantities between turns).
- 2026-09-03 / LLM client robustness: transient retries extended from 429-only to also cover 400s carrying provider-backend markers (backend/upstream/provider returned error) and 200s with no usable choices; max_attempts configurable. Empty-200 retry pinned by test_empty_choices_retried_then_succeeds.
- 2026-09-03 / Wire-format fix (found by NVIDIA NIM): assistant tool_calls replay messages now serialize per OpenAI spec {id, type:"function", function:{name, arguments:<json string>}} with the same id (synthesized call_N if the provider omits one) on the paired role=tool result. OpenRouter tolerated the old {name, arguments} shape; strict providers 400 "missing field function".
- 2026-09-03 / Receipt lines carry product names: /cart, /checkout (prepare/confirm/GET), and /orders (POST/GET) responses join line items against the catalog at the API boundary (_name_items/_with_names in app/api/routes.py; same in the mock). Persisted CartItem models are untouched (pydantic ignores the extra key) — the join is display-only.
